Gaugepack · A private line

What your phone runs. Read it, and check it.

"Nobody can read it, not even us" is only worth something if you can check. The weak point of any page that seals on the phone is the page itself: whoever serves it could serve a bad one. So the page is checked three ways, here, in your own browser.

The three checks, in plain words

  • The server's word. The mailbox says what it is serving; your browser compares it with what it got. This catches a page changed on the way to you.
  • The published list. Every version of every page file is published, with its fingerprint, in a public repository we do not control the history of once it is written: github.com/TentaPack/Gaugepack-line-page. Each release is a signed tag; the list only ever grows. Your browser fetches that list from github.com, not from us, and checks every file it received against it. A file not on the list means one of two things: we published a new version minutes ago, or this phone was given code nobody else can see. The second is the attack this exists to catch.
  • The pin. Your phone's service worker keeps the page it verified and serves that copy. When a new version appears it fetches the new files, checks each one against the published list, and only then switches. If a file is not on the list, it refuses the update, keeps the old version, and tells you. Two vendored files, the code drawer and the MP3 encoder, also carry an integrity hash in the page itself, so a swapped copy is not even run.

What this does and does not promise

We can be forced to publish bad code. If a court or a thief made us ship a page that leaks keys, it would go on the published list like any release, signed, in public, for anyone to read and compare with the last one. What we cannot do is give one person different code without it being detectable: a page that is not on the list fails these checks on that phone and is refused by its pin. The list is public precisely so that we cannot quietly change our own story.

What this cannot catch: a phone that is already compromised, a browser that lies about what it fetched, and the first visit on a browser with no service worker, which runs the page unpinned (this page still checks it against the list). The mailbox's own code is not published; it holds sealed noise and the register, and its behaviour is what the page's code, above, lets it hold.

What to look for in the code

  • In line.js: the secret is read from after the # in the address (location.hash), which browsers never send to any server. The key is derived from it on the phone; seal and open are AES-GCM on the phone.
  • Every fetch and the WebSocket go to this site only, and carry only sealed text, a session tag, and a device hash; the one outside fetch is the published list on github.com, which carries nothing. Search for fetch( and count.
  • What the mailbox holds per message is { s, c, t, d } (tag, sealed text, time, device hash), deleted on "got it" or after 24 hours; there is no decryption anywhere because there is no key anywhere.
  • The tally (/api/count) receives one word with nothing attached. The register holds room ids (hashes), dates and a label. Neither holds a message.

To check by hand: clone the repository, git verify-tag a release with the allowed_signers file in it, hash the files in page/, and compare with the fingerprints above. Status of the mailbox: line.gaugepack.com/status. Privacy: what we hold.
